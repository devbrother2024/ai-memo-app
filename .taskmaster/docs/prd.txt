# 📝 PRD: **Memora** – AI 음성 메모장 웹서비스

---

## Overview

**Memora**는 AI 기반 웹 메모 애플리케이션으로, 사용자의 음성 또는 텍스트 입력을 받아 AI가 자동으로 요약 및 분류해주는 서비스입니다. 기존 메모 서비스의 단순 저장 기능을 넘어서, STT(Speech-to-Text) 기술을 활용한 빠른 음성 메모 작성과 AI 기반 자동 정리 기능을 제공합니다.

### 문제 해결
- 긴 메모 내용의 효율적인 요약 및 정리
- 음성 기반 빠른 메모 작성의 어려움
- 체계적인 메모 분류 및 검색의 부재
- 웹 기반 접근성과 실시간 동기화 필요

### 대상 사용자
- **직장인/프리랜서**: 회의나 작업 중 빠른 메모 작성 및 정리
- **대학생**: 수업 내용의 음성/텍스트 기록 및 정리
- **일반 사용자**: 일상 메모 작성 및 필요시 검색

### 가치 제안
- AI 기반 자동 요약으로 핵심 정보 추출
- 실시간 STT를 통한 빠른 음성 메모 작성
- 자동 카테고리 분류로 체계적인 정리
- 웹 기반 접근성으로 언제 어디서나 사용 가능

## Core Features

### 1. 음성 메모 작성 (Voice Memo Creation)
- **기능**: 마이크를 통한 음성 입력을 실시간 텍스트로 변환
- **중요성**: 빠른 메모 작성으로 사용자 편의성 극대화
- **동작 방식**: Web Speech API 또는 외부 STT 서비스 활용

### 2. 텍스트 메모 작성 (Text Memo Creation)
- **기능**: 사용자가 직접 웹에서 텍스트 입력
- **중요성**: 음성 입력이 어려운 환경에서의 대안 제공
- **동작 방식**: 실시간 에디터를 통한 직관적인 텍스트 입력

### 3. AI 자동 요약 (AI Auto-Summarization)
- **기능**: 긴 메모 내용을 핵심 포인트로 자동 요약
- **중요성**: 중요한 정보를 빠르게 파악 가능
- **동작 방식**: OpenAI GPT 또는 유사 AI 모델 활용

### 4. 자동 카테고리 분류 (Auto-Categorization)
- **기능**: 메모 내용을 주제별로 자동 분류
- **중요성**: 체계적인 메모 관리 및 검색 효율성
- **동작 방식**: AI 모델을 통한 텍스트 분석 및 분류

### 5. 검색 및 필터링 (Search & Filtering)
- **기능**: 키워드, 작성일, 카테고리별 검색
- **중요성**: 필요시 빠른 메모 찾기
- **동작 방식**: 데이터베이스 인덱싱 및 검색 알고리즘

### 6. 데이터 동기화 (Data Synchronization)
- **기능**: 모든 메모를 서버 DB에 저장 및 동기화
- **중요성**: 데이터 안전성 및 다중 기기 접근
- **동작 방식**: RESTful API를 통한 CRUD 작업

## Technical Architecture

### 시스템 컴포넌트

#### 1. 프론트엔드 & 백엔드 (Next.js)
- **기술 스택**: Next.js 14, TypeScript, Tailwind CSS
- **주요 기능**: 
  - Web Speech API를 통한 음성 인식
  - 실시간 텍스트 에디터
  - 반응형 UI 컴포넌트
  - 상태 관리 (Zustand/Context API)
  - API Routes를 통한 백엔드 기능
  - 서버 사이드 렌더링 (SSR)

#### 2. 데이터베이스 (Supabase)
- **기술 스택**: Supabase, DrizzleORM, PostgreSQL
- **스키마 설계**:
  ```sql
  users (id, email, name, created_at)
  memos (id, user_id, title, content, summary, category, created_at, updated_at)
  categories (id, name, color)
  ```
- **인덱싱**: 검색 성능을 위한 텍스트 인덱스
- **실시간 기능**: Supabase Realtime을 통한 실시간 동기화

#### 3. AI 서비스 연동
- **Anthropic Claude**: 메모 요약 및 카테고리 분류
- **Web Speech API**: 브라우저 내장 음성 인식
- **대안**: Google Cloud Speech-to-Text, Azure Speech Services

### API 설계

#### 메모 관련 API
```
GET    /api/memos          # 메모 목록 조회
POST   /api/memos          # 새 메모 생성
GET    /api/memos/:id      # 메모 상세 조회
PUT    /api/memos/:id      # 메모 수정
DELETE /api/memos/:id      # 메모 삭제
POST   /api/memos/:id/summarize  # AI 요약 생성
```

#### 사용자 관련 API
```
POST   /api/auth/login     # 로그인
POST   /api/auth/register  # 회원가입
GET    /api/auth/profile   # 프로필 조회
```

### 인프라 요구사항
- **호스팅**: Vercel (풀스택 애플리케이션)
- **데이터베이스**: Supabase (PostgreSQL 기반)
- **파일 저장**: Supabase Storage
- **도메인**: 커스텀 도메인 설정

## Risks and Mitigations

### 기술적 도전과제

#### 1. 음성 인식 정확도
- **리스크**: Web Speech API의 정확도 한계
- **완화 방안**: 
  - 다중 STT 서비스 연동 (Google, Azure)
  - 사용자 수동 편집 기능
  - 음성 품질 개선 가이드

#### 2. AI 요약 품질
- **리스크**: OpenAI API 비용 및 응답 시간
- **완화 방안**:
  - 요약 캐싱 시스템
  - 대안 AI 모델 검토
  - 사용자 피드백 시스템

#### 3. 데이터베이스 성능
- **리스크**: 대용량 메모 데이터 처리
- **완화 방안**:
  - 데이터베이스 인덱싱
  - 페이지네이션 구현
  - 아카이빙 시스템

- **리스크**: 단일 개발자로 인한 개발 속도 한계

## Appendix

### 기술 스택 상세

#### 프론트엔드 & 백엔드
- **Framework**: Next.js 14 (App Router)
- **Language**: TypeScript
- **Styling**: Tailwind CSS
- **State Management**: Zustand
- **UI Components**: Headless UI / Radix UI
- **Icons**: Lucide React
- **API**: Next.js API Routes
- **Database**: Supabase
- **ORM**: DrizzleORM
- **Authentication**: Supabase Auth

#### AI 서비스
- **Text Generation**: Anthropic Claude
- **Speech Recognition**: Web Speech API
- **Alternative**: Google Cloud Speech-to-Text

### 성능 목표
- **페이지 로드 시간**: < 2초
- **API 응답 시간**: < 500ms
- **음성 인식 정확도**: > 90%
- **AI 요약 품질**: 사용자 만족도 > 80%

### 보안 고려사항
- **데이터 암호화**: AES-256
- **API 보안**: Rate Limiting
- **인증**: JWT with Refresh Token
- **데이터 백업**: 자동 백업 시스템

### 확장성 계획
- **마이크로서비스**: 기능별 서비스 분리
- **캐싱**: Redis 도입
- **CDN**: 정적 자원 최적화
- **모니터링**: 로그 분석 시스템
